I stopped incrementing my version numbers for a while and the mess it made has changed how I name releases.

I'd been bumping the patch digit for anything, so every version looked equally important. Six releases all ending in a different third digit, and no way to tell from the name whether one of them fixed a data loss bug or a typo.

Now the number answers one question. Does the data need a migration. If it does, the first digit goes up. If it doesn't and there are behaviour changes, the second goes up. Otherwise the third moves.

Nobody outside my own projects reads these numbers, which is the point. They're for me at two in the morning when something broke and I need to know whether rolling back is safe.

A version is a promise about compatibility. If it promises nothing, it's decoration with a dot in it.
